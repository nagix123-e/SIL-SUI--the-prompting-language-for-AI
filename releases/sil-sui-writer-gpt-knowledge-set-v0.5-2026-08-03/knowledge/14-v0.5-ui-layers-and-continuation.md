# SIL/SUI v0.5 — UI Layers and Continuation

v0.5 keeps every v0.1–v0.4 form readable and makes two changes to new writing:

1. SUI has explicit layers for a production UI's design system, responsive behavior, accessibility, navigation, bindings, and data model.
2. A precise unregistered SemanticRef is a review item, not a reason to reject or halt an otherwise valid contract. It stays lossless and is never represented as a Core preset.

## SUI design layers

Use the following named blocks inside `ui Name:` when the layer matters to the requested screen. These are declarative specifications, not CSS, JSX, API calls, or routing code.

| Block | Records | Typical fields |
| --- | --- | --- |
| `design Name:` | Design tokens and visual system intent | `token`, `theme`, `density`, `motion`, `purpose` |
| `responsive Name:` | Breakpoints and layout behavior | `strategy`, `breakpoint`, `min_width`, `max_width`, `overflow` |
| `accessibility Name:` | Keyboard, labels, semantics, contrast, motion | `require`, `role`, `label`, `announce`, `focus` |
| `navigation Name:` | Routes, modal flow, history, unsaved changes | `behavior`, `from`, `event`, `to`, `fallback` |
| `binding Name:` | Explicit UI-to-state/output correspondence | `source`, `target`, `transform`, `update` |
| `data Name:` | UI data model, field rules, formats, list states | `model`, `field`, `schema`, `empty`, `loading`, `error` |

Use clear English SemanticRefs and retain exact proper nouns as extensions. A small static confirmation dialog may legitimately omit `navigation`, `binding`, or `data`; omission creates an advisory review notice, never a syntax failure.

```sui
ui AccountSettings:
    version: 0.5
    screen: account_settings
    component SettingsForm:
        kind: form
    design Foundation:
        token: color.semantic
        token: spacing.scale
    responsive Compact:
        strategy: reflow.stack
    accessibility Baseline:
        require: keyboard.complete
        require: screen_reader.labels
    navigation SaveFlow:
        behavior: route.back
    binding SettingsState:
        source: state.account_settings
    data SettingsModel:
        model: account.settings
        field:
            display_name
            email
    state:
        view.default
        view.loading
        view.error
    verify:
        settings.save_visible
    on_failure:
        ui.show_error_state
        diagnostics.preserve
```

## Continuation rule

The Runner reports these facts separately:

- `valid`: grammar and mandatory structural checks passed.
- `executionReady`: the contract has the static fields necessary for a bounded handoff. This is not host authorization.
- `semanticInteroperable`: every reference is Core, locally declared, structurally resolved, or evidence-resolved.
- `continuation: continue_with_review`: the host may continue analysis, planning, formatting, or other separately-authorized work while it lists unresolved extensions.

Only malformed syntax, contradictory definitions, missing required bounded-loop parameters, or a true safety/phase hard block produces `continuation: blocked`. Do not use an unknown product name, domain noun, implementation verb, or precise local reference as a reason to stop.

When an unregistered reference appears, preserve it exactly, classify it (`extension.proper_noun`, `extension.verb`, or another extension marker), and add a concise review item. The Writer must not invent a Core code, silently rewrite meaning, or claim web/repository evidence without a host supplying that evidence.
