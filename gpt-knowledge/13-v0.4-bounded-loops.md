# SIL/SUI v0.4 — Bounded Loops

v0.4 adds declarative repetition. It is not Python or an execution runtime: a Runner records and validates bounded work; a host may only execute an approved plan with independent tool permission.

## Safety rules

- Never write `while`, `for`, expressions, assignments, callbacks, or executable conditions.
- Every task loop has an integer `max_iterations` from `1` through `10000`.
- A task loop has a non-empty `body:` block. Loop nesting may not exceed three levels.
- `until` has a declarative `condition:` reference and still requires a finite maximum.
- A loop declaration does not authorize repository edits, network access, tool calls, or repeated external actions.

## Task loops

Use `for_each` to process a declared collection, `repeat` for a finite fixed attempt count, and `until` for a finite convergence/check cycle.

```sil
task EvaluateBenchmarks:
    version: 0.4
    goal: effectiveness.confirm
    target: benchmark.results
    action: evaluate

    for_each Benchmark:
        over: input.benchmark.tasks
        as: benchmark
        max_iterations: 100
        body:
            require: benchmark.configuration.fixed

    repeat RetryCollection:
        max_iterations: 3
        body:
            verify: collection.retry_observed

    until Converged:
        condition: evaluation.converged
        max_iterations: 12
        body:
            verify: evaluation.metrics.measured

    verify:
        evaluation.results.traceable
    on_failure:
        task.abort
```

`over` is a declared collection reference. `as` is a lowercase English identifier, not an expression. `condition` is a named observable condition, not executable code. Keep the loop body declarative and preserve `verify` plus `on_failure` at task level.

## SUI collection rendering

`render_each` is a UI template declaration, not an action loop. Nest it under its owning component. It requires one collection, item name, stable key, finite `max_items`, and template component.

```sui
ui EvaluationDashboard:
    version: 0.4
    screen: effectiveness_dashboard
    component ResultList:
        kind: list
        render_each ResultRow:
            over: output.evaluation.results
            as: result
            key: result.id
            max_items: 100
            component ResultRow:
                kind: row
                bind: output.evaluation.results
```

Use `max_items` for visible rendering work. Define empty, loading, error, and pagination/virtualization states separately when needed. Do not put `render_each` outside a `ui` block or use an unstable list index as `key` when an item identity exists.

## Writer decision rule

Only emit a v0.4 loop when the user explicitly requests repetition, batch processing, a bounded retry, or collection rendering and supplies (or safely permits you to state) a finite bound. Otherwise keep the work as a single declarative task and add a review warning for the missing bound.
